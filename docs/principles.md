# Principles

The principles that decide what the project collects and how it presents it. They hold for this
dataset and for the tools and databases built around it.

## Collect first

Writing is studied from its examples, so the first task is to gather them: every written form from
every writing culture of the Sinosphere, Han-derived scripts first. The aim is humanities
informatics, engineering methods applied so that research on writing is faster, more precise and
grounded in evidence.

## Access is the only concern

Whether a form looks interesting, how it should be read, whether Unicode encodes it, or which
character set already holds it decides nothing about inclusion. Collect as many forms as broadly as
possible. Interpretation belongs in annotations with their own evidence, never in the choice of
what to keep.

## Trace to the original

Every record leads back to the page or object it was read from, with enough metadata to check it.
Prefer the earliest attestation in its original source, so the data can serve the history of
forms and of words.

## Machines first, people for the rest

OCR, alignment and clustering do the bulk of the work. Variants and characters without a code point
still need people, so review and crowdsourcing are part of the design. The goal is to shrink human
work, while showing where it is still needed.

## Open and volunteer

The data and code are open. No money changes hands for inclusion; running costs are covered by the
maintainer and by donations.

## Credit and good faith

Material from others is included with a quotation or excerpt, a link and an explicit source, and the
provider's name is shown as they ask. Material from a partner goes in only once the partner agrees,
and never against their interest.

## Built to be reused

Intended uses include example collections for dictionaries, models for calligraphy and type design,
and training data for OCR and machine learning. Formats, licences and identifiers are chosen so a
user can take the subset they need.

## Ask the community

Suggestions on which sources to add, where a character occurs, what is wrong and what would make the
data more useful are welcome through the issue tracker.
